# Swiftix Go Toolchain Contract

> Last verified: 2026-10-13<br>
> Scope: `SwiftixGo`, `SwiftixGoRuntime`, `SwiftixGoTool`, and `SwiftixGoHost`

Swiftix Go accepts Go source, compiles it to `swiftix/svm64` bytecode with a pure Swift compiler, and executes it in its own VM as a real Swiftix process. It neither embeds the host Go runtime nor presents itself as an official Go distribution.

The implementation uses Go 1.24 as a specification reference but promises only the subset recorded here. Unsupported behavior must return an explicit error instead of silently approximating the semantics.

## User Contract

| Item | Behavior |
| --- | --- |
| Source | `*.go` and `*_test.go`; one module with multiple local packages |
| Tools | `go`, `gofmt`, and `go fmt` |
| Entry point | `package main` with `func main()` |
| Target | `GOOS=swiftix` and `GOARCH=svm64` |
| Artifact | Versioned Swiftix executable image, not ELF or Mach-O |
| Determinism | Identical source, tool version, and target metadata produce identical bytes |

Typical workflow:

```text
go mod init example/hello
go fmt ./...
go test ./...
go build -o hello .
./hello
```

### Known Gaps

- `context` is written in Go. `net` serves IPv4 TCP only: no UDP or Unix sockets, no DNS beyond `localhost`, `localhost` is `127.0.0.1` where Go tries `[::1]` first, and `DialTimeout` ignores its timeout. There is no `ListenTCP`, `DialTCP`, `CloseWrite`, or `SetKeepAlive`, and `%v` of a `*net.TCPListener` has no `lc` field. `net.Dial` reports a refused connection and an abandoned handshake as errors; a write to a connection the peer reset still succeeds.
- Complex types are not provided. `==` on interface, struct, and array values that hold floats, and on float map keys, compares the bits, so a NaN equals itself and `+0` differs from `-0` there; direct comparisons and `switch` are IEEE. There is no `math.Log`, `Exp`, or trigonometry, and no `sort.Float64Slice`. A float constant with an integer value is no index (`s[2.0]`). Duplicate cases of typed constants in a switch are not detected, the assignment form `for i = range x` is not parsed, and a type switch or an assertion on a library interface (`context.Context`) is refused.
- `append(s, a, b)` with several values stores those that fit before it grows the slice, where Go stores none in the old array. `&m[1].x` fails in the compiler with `bytecode operand type mismatch` where Go says the address cannot be taken. `==` on struct and array values that hold interfaces whose dynamic type is incomparable does not panic as Go's does.
- The value of a blank constant (`const _ = ...`) is not checked, and a blank function is emitted as dead code. A package-level `iota` declared in another file of the package does not hide the generator. An unexported field reached through a struct type without a name, or through a type defined over another package's struct, is not checked.
- The error of a failed method of `*os.File` (`Read`, `Write`, `Close`, ...) and of `os.Getwd`, `os.Hostname`, and `os.Setenv` is its message only. Two of them with the same text compare equal, where Go makes a new value each time; `%T` reports `*errors.errorString` where Go has `*fs.PathError`; and the message lacks the file's name (`close: file already closed` where Go says `close go.mod: file already closed`). A short write fails with the run time's `short write`, not `io.ErrShortWrite`, `%T` of `os.ErrDeadlineExceeded` is `*os.deadlineExceededError` and of `net.ErrClosed` `net.errNetClosing`, where Go names the types of `internal/poll`. Errors a program makes with `errors.New`, `fmt.Errorf`, or its own types do not have this limit.
- The goroutine trace of an unrecovered panic (see "Panics") has no `created by` line. Goroutine numbers are the VM's, the offset after a line is the offset of a VM instruction, and a frame prints no argument words, as Go prints an inlined one; lines are those of statements, and a built image has none and prints `?:0`. `runtime` has only `runtime.Error`: `runtime.NumGoroutine` and the rest are undefined.
- `net/http` has no `BaseContext`, `ConnContext`, or `LocalAddrContextKey`, and a dial is not interrupted by a context; no cookies, `BasicAuth`, multipart forms, or hijacking (a reverse proxy does not pass an upgrade); the client sends no `Accept-Encoding: gzip`, uses a connection for each request, takes an IPv4 literal or `localhost` as host, and has no TLS. `defer delete(m, k)` is not accepted.
- `errors.As`, the functions of `net/http`, and the methods of `*testing.T` cannot be values; a `context.CancelFunc` is not a `func()`; `%T` of a library function shows `int` where Go has `int64` or `fs.FileMode`, and `*os.File` where Go has `io.Writer`. `sort.Slice` given a non-slice panics with Go's text as a string, and the older separate-compilation interface does not link the library's Go text.
- `strings.Builder.Cap` and `append` follow this VM's growth (doubling), not Go's size classes. A loop over bytes costs about 22 VM instructions per byte. `ReadString`, `Text`, and `Buffer.String` repair invalid UTF-8 to U+FFFD, and so does a string sliced inside a character.
- A mutex prints as `{<mutex>}` where Go prints `{{} {0 0}}`, and `sync.Mutex{}` is no composite literal; a struct that embeds `sync.Mutex` does not satisfy an interface that asks for `TryLock`. A stopped timer leaves a no-op entry on the event loop until its deadline, and `len(t.C)` of a fired, unread timer is 1. `log` has no time zone (local time is UTC) and prints `???:0` for `Lshortfile`; `sync/atomic` has no `Pointer[T]`, `Uintptr`, or `And`/`Or`; `atomic.Value` tells types apart by their `%T` names; `sync.Map.Range` visits in insertion order; `sync.Pool` never drops a value. The initial order of `os.Environ` is by name.
- Compile errors are Go's, word for word and at Go's position, for type errors; syntax errors keep wording of their own (`expected type` for Go's `syntax error: unexpected newline, expected type`). A message prints `int32` for `rune`, `byte` for `uint8`, `any` for `interface{}`, and the type an alias stands for; a function type of the library has no parameter names; a hexadecimal literal is printed in decimal; a named boolean constant is described without its value; a constant expression that overflows keeps its parentheses (`(x + 100)`); a method expression of a library interface that lacks the method (`fmt.Stringer.Foo`) is reported in wording of its own. `5 % 2.0` is reported as mismatched untyped types where Go says `%` is not defined on a float. An unexported name of another package is always `name x not exported by package lib`. Types, signatures, and package-level variables are checked before function bodies, so with several errors the first reported may be a later one than Go's.
- In a call with several arguments the function variable, receiver, or element is read before the arguments, where Go reads it after; only the forwarded form `f(g())` follows Go's order.
- `t.Error` and `t.Fatal` print a duration as its integer.
- An array length cannot name a constant of another package (`[lib.N]T`); a package of the library named only in an array length is `imported and not used`, and one imported under another name is invalid there; and `len` of a string constant declared in a function is not folded in one. The index of an array or slice element must be a literal, a constant of the program or the library, or arithmetic over those, and a composite literal has at most 1,048,576 elements.
- Go lists every error of a package; Swiftix Go reports one, the first in the order of the source. It finds the first that Go finds for an unused variable beside another error; elsewhere the choice among several errors may differ.
- Guest strings are always valid UTF-8, so `string(b)` for a `[]byte` repairs each invalid sequence to U+FFFD instead of keeping the bytes; `[]byte(s)` yields the exact UTF-8 bytes.
- A shift whose result is an `int` or an `int64`, with a `uint64` count of 2^63 or more, panics as a negative shift where Go shifts everything out. A predeclared numeric type name cannot be redeclared (`type int64 int`). Indexing a `map[any]T` with a typed key does not box the key. The builtin `println` is not provided.
- `time.Time` has no monotonic reading (`String` prints no `m=+...`) and there is no zone database: `time.LoadLocation` knows only `UTC` and `Local`. Locations compare by value, so two `time.FixedZone` calls with the same name and offset are equal where Go's are different pointers. A parse error is Go's message but not a `*time.ParseError`, and there is no `UnmarshalText`, `MarshalJSON`, or `MarshalBinary`. `*os.File` is likewise opaque: it cannot be dereferenced, and it has no `Stat`, `Truncate`, `Chmod`, or directory reads. `os.Open` refuses a directory.
- `gofmt -s` implements only its registered safe rules.
- A struct type written in place has its promoted methods in direct use but implements no interface through them. Unexported promoted names of another package's type are not hidden, and an interface that embeds a non-interface type is reported where it embeds it.
- `http.Transport` keeps no idle connections, ignores `Proxy`, and has no TLS or HTTP/2; a `ResponseController` cannot hijack a connection, so `httputil.ReverseProxy` cannot pass a protocol upgrade (WebSocket). `mime/multipart` and `net/textproto` are not packages a program can import: `FileServer`'s responses of several ranges use a writer of `net/http`'s own, with a boundary from `math/rand`. `mime.TypeByExtension` reads the `mime.types` files of the system, which Swiftix has none of: it knows Go's built-in table.
- `encoding/binary` encodes and decodes fixed-size values and slices of them, and refuses a struct (Go's `reflect` path) with Go's message for a type it cannot encode; `binary.Size` of one is -1. `math` has no `Sin`, `Cos`, `Log2`, `Log10`, `Log1p`, `Expm1`, `Hypot`, `Cbrt`, `Frexp`, or `Ldexp` yet. `math/rand/v2` (generic) is not provided, and `rand.Seed` is the no-op of Go 1.24.
- `flag` records `?:0` for where a flag set before it was defined was set, and `TextVar` sets its variable through `MarshalText` and `UnmarshalText`. `print` and `println` print an address as a fixed value. The kernel ends a process on SIGINT, SIGPIPE, and SIGTERM by default and ignores SIGHUP, SIGQUIT, SIGUSR1, SIGUSR2, and SIGALRM, which Linux ends it on; a program's own unhandled signal is Go's under `go run` and as a process. A Ctrl-C at the host's terminal is not a signal to a program run by the host's `swiftix-go run`.
- `gofmt` does not reformat doc comments as `go/doc/comment` does (it merges no blank lines and rewrites no `/* */` doc comment).
- The error types of `encoding/json` have no `reflect.Type` or `reflect.Value` fields; their `Error()`, `%T`, other fields, and `errors.As` are Go's, and `%+v`/`%#v` of them show the type's text in an unexported field. A slice grown by `Unmarshal` doubles its capacity. A pointer method `UnmarshalJSON`/`UnmarshalText` on a field that is not a pointer gets the address of a copy, written back after it returns; decoded values are written when each value completes, so a method that changes the same data mid-decode sees different partial effects. `Time.UnmarshalJSON` errors are plain errors with Go's text. Printing a value nested about ten thousand deep with `fmt` overflows the host's stack, where Go prints it.
- A file-backed process has no CPU quota: yielding keeps the system responsive, and the host or user ends a runaway program with a signal.
- The compiler frontend still needs tighter budgets for source, AST, imports, and constants.

### Explicitly Unsupported

- Generics, reflect, cgo, assembler, plugins, the host C ABI, and native machine-code linking.
- Complex types, which are rejected by name.
- Dereferencing an `os.File`.
- `fmt.Sscanf` and the other scanning functions, and `fmt.Append*`.
- Benchmarking, coverage, profiling, `go vet`, `go work`, `go.sum`, and direct `GOPROXY` access.
- `crypto/*`, `compress/*`, `archive/*`, and `math/big`.
- Go binaries for other platforms or any path that bypasses Swiftix to access host files, processes, or networking.

The presence of a package name does not imply compatibility with the full official API.

## Tools and Modules

```text
go version
go env [NAME ...]
go mod init MODULE
go fmt [FILE | . | ./...]
go run PACKAGE [args ...]
go test [PACKAGE | ./...]
go build [-o FILE] [PACKAGE | ./...]
go install [PACKAGE]
go clean -cache
```

`gofmt` supports files, directories, stdin, `-l`, `-w`, `-d`, the AST-pattern `-r` option, and limited `-s`. A rule is `pattern -> replacement`, two expressions. As in Go, an identifier of the pattern that is one lower-case letter stands for any expression and every other identifier matches itself; the operands of an expression are rewritten before the expression is matched, so a rule applies at every depth (`f(f(1))` under `f(1) -> 1` is `1`); an operand in parentheses is matched with them, and parentheses in a pattern match parentheses, so `(a) -> a` removes every pair; and a rule from one identifier to another renames it wherever the file has it, the name of a declaration, a field, or a type included. A single letter alone (`x -> y`) rewrites every expression, where Go's also meets the names of declarations; neither result is a program. Output must be deterministic and idempotent; batch writes begin only after every file parses successfully.

The blanks around binary operators follow Go's printer rule for rule, so source that Go's `gofmt` formatted comes back unchanged: precedence shows at the top of an expression (`x*2 + y`), and an operator inside the arguments of a call that has several, inside an index, among several values of an assignment, or under an operator of another precedence is joined to its operands (`f(a+1, b)`, `s[i+1]`, `a, b = b+1, a*2`, `n-1 < len(s)`). Parentheses take one level back (`(a + b) * c`), an operator stays clear of a unary one after it (`a - -b`), and the `:` of a slice has blanks beside a binary bound (`s[lo : hi+1]`). Parentheses that say nothing are dropped: the second pair of `((x))` and the pair around a whole `if`, `for`, `switch`, or `range` expression. An empty line separates top-level declarations of different kinds; between two of one kind the source decides.

Beyond the spacing of tokens `gofmt` does what Go's printer does with lines and columns:

- **Columns.** The printer of Go writes through a tabwriter, and so does this one: the name of a struct field, a comment at the end of a line, the body of a one-line function declaration, and the key of a composite literal element that begins a line each end a cell, and the cells of consecutive lines of one indentation are padded to one width. A line without the cell, an empty line, a `case`, and a function that spans several lines start the columns over, and so does a literal element whose size is far from that of the ones before it (Go's rule: both over 40 columns and off the geometric mean by a factor of 2.5).
- **One line.** A function stays on the line of its signature when the source has it there, it has at most five statements, none of which needs a line of its own, and signature and statements take no more than 100 columns: `func (s *stack) empty() bool { return len(s.items) == 0 }`. A `struct` or `interface` stays on one line when it has one field or method whose type takes no more than 30 columns: `interface{ Area() int }`. The blocks of `if`, `for`, and `switch` always open a line.
- **Line breaks.** A line break of the source is kept after a binary operator, between the arguments of a call, the parameters of a function, the elements of a composite literal, and the values of an assignment, `return`, or `case`, after `=`, and after the `.` of a selector. What follows is indented one level until the construct ends; constructs inside one another add up. A closing `)` or `}` on a line of its own, after the final comma, returns to the indentation of the line that opened the list; where the whole list is on the line of its opening delimiter, a final comma is dropped.

- **Groups.** A declaration group has each specification on a line of its own, indented, between `(` and `)`; a group without any is `()`. The imports of a group are sorted by path within each run of successive lines, each with the comment at the end of its line, and one that is there twice is kept once; an empty line or a comment on a line of its own ends a run. In a `var` or `const` group of several specifications the names, the types, the values, and the comments are columns. The column of types is kept, empty, for a value without a type when a value beside it has one (`x          = 7` under `foobar int = 42`), and otherwise values stand in it. The names of the types of a `type` group are a column too.

Every Go source file of the coreutils, sysutils, and editors packages, which Go's `gofmt` formatted, comes back from this `gofmt` unchanged.

`go build`, `go run`, and `go install` take one package directory below the current one (`.`, `./cmd/tool`; `go run` needs the `./` form) or a list of `.go` files; a file list is compiled as a single package without local imports. `go test` takes `.` or `./...`, and a package's test files may import local packages that its other files do not.

Default guest paths:

```text
GOPATH=/home/<user>/go
GOBIN=/home/<user>/go/bin
GOCACHE=/home/<user>/.cache/go-build
GOMODCACHE=/home/<user>/go/pkg/mod
```

Module support includes one module, multiple local packages, `replace` within the same VFS, and external dependencies already present in `GOMODCACHE`. The toolchain does not download modules from the network; `pkg` installs dependencies. The build cache uses a SHA-256 content key that covers the tool version, ABI, target, `go.mod`, the root package's import path, and the path and text of every source file of every package in the build, so a change to an imported package is a miss. Corrupt entries are treated as misses.

### Packages and Linking

A build is one `package main` plus every local package it reaches through imports. `GoCompiler.compile(packages:root:)` takes the packages by import path, and `GoCompiler.compile(root:sources:)` asks a callback for each one on demand; the `go` tool and the `coreutils` package builder both use this path. An import path that names a runtime package (`fmt`, `os`, `strings`, `swiftix/userland`, ...) is never looked up as a local package.

- **Linking model.** Packages are linked as source, not as separately compiled objects: every package-level name `X` of the package with import path `p` becomes the program symbol `p.X` (for example `example/app/internal/text.Join`), methods follow their type (`p.T.Method`), and a qualified reference `q.X` resolves to that symbol before type checking. Names of different packages therefore never collide, even when two packages share a package name, and the main package keeps its plain names. A package whose name is not the last element of its import path has the name in its symbols, after the path (`example/app/v2@api.Request`), because Go prints a type by its package's name (`api.Request`) and the symbol is all the VM has of it. Diagnostics print Go spelling (`lib.Point`, not the symbol), and name a package as the file that is reported names it.
- **What crosses a package boundary.** Functions with zero, one, or several results (`a, b := pkg.F()`, `return pkg.F()`); typed and untyped constants, which keep adapting to `byte` and named integer types in the importing package; variables, which are one shared storage location that any importer may read, assign, increment, or take the address of; named types, struct types with exported fields (`pkg.Point{X: 1}`, `p.X = 2`), their value and pointer methods, interfaces, and type assertions to an imported type. Each works to the extent the in-package form does.
- **Cost.** A cross-package call, constant, or variable access compiles to exactly the instructions of the in-package form: one `call` instruction per call, and no thunk, lookup, or indirection. The image carries no package table.
- **Initialization.** Packages initialize in dependency order, each exactly once however many packages import it: first its package-level variables (in Go's order: each time the first, in source order, that reads no variable still to be initialized), then its `init` functions in source order. The image's initializer list holds `$<import path>.init` for each imported package's variables, `$package.init` for the main package's, and `$init.N` for `init` functions.
- **Rules.** `cannot refer to unexported name pkg.x` and `undefined: pkg.X` for package-level names; `cannot refer to unexported field x` or `method x` for a member of another package's type, `cannot refer to unexported field x in struct literal of type lib.T`, and `implicit assignment to unexported field x in struct literal of type lib.T`; `import cycle not allowed: a imports b imports a`; `"path" imported and not used` for a package the file never names, local or of the run-time library, or `"path" imported as name and not used` when its name in the file is not the last element of its path; `name redeclared in this block` for two imports of one name; `use of package name not in selector`; `import "path" is a program, not an importable package`; `use of internal package path not allowed` when a package below an `internal` directory is imported from outside the tree rooted at that directory's parent; `found packages a and b` for mixed package clauses; and `package path is not available` for an import that is neither local nor provided by the runtime. The qualifier is the name the import gives, or else the imported package's declared name. A package imported as `_` is linked and initialized and needs no use; one imported as `.` lends the file its exported package-level names, which a declaration of the file's own package or of an enclosing block hides. Diagnostics are reported at the import's name, or at its path when it has none.
- **Limits.** One build holds at most 1,024 packages, and the `go` tool follows import chains at most 128 packages deep; larger builds are refused with a diagnostic.
- `GoCompiler.compilePackage` and `compile(sources:importedPackages:)` remain as the older separate-compilation interface, which resolves only single-result functions of an imported package. New code should use the module build.

## Runtime and System Integration

```text
SwiftixGo          parser → type checker → IR → bytecode
SwiftixGoRuntime   image → VM → heap/GC → goroutine/channel
SwiftixGoTool      go/gofmt, module graph, cache
SwiftixGoHost      host-file adapter and CLI
```

- `GOMAXPROCS=1`; runnable work uses deterministic FIFO ordering, and select uses fair choice.
- Each executable corresponds to one Swiftix process and shares its argv/env/cwd/file descriptors/signals.
- The standard library reaches the guest VFS and network only through the `ProcessContext` syscall bridge.
- `GoRuntimeResourceLimits` bounds images, heap, collections, goroutines, timers, handles, and I/O.
- `swiftix/userland` provides the terminal ABI for full-screen programs:
  `ReadStdin() (string, int)` returns the next fd 0 chunk (at most 4096 bytes,
  never splitting a UTF-8 sequence) with status 0, or status 1 at end of input;
  `WriteFile(path, data string) int` creates or truncates a VFS file and returns
  0 or 1; `SetRawMode(enabled bool) bool` switches the fd 0 terminal and reports
  `false` when fd 0 is not a terminal; `WindowSize() (int, int)` returns rows
  and columns of the fd 1 (or fd 0) terminal, or `(0, 0)`. There is no
  `SIGWINCH`; programs re-read `WindowSize` after input.
- File-backed executables (`GoExecutableLoader`, built on
  `GoVirtualMachine.startProcess`) run cooperatively as the body of their
  process and never drive the event loop themselves:
  - **CPU.** After each instruction quantum (4,096 instructions) the process
    yields to the event loop (`ProcessContext.yield`) and continues in a later
    step, so other processes run in between and a signal such as Ctrl-C ends a
    runaway program. `ps` shows it running (`R`). There is no total
    instruction cap; `startProcess(instructionBudget:)` sets one for a host
    that wants it.
  - **Time.** A program that never blocks does not stop logical time. Under
    `EventLoop.advance(by:stepBudget:)`, a timer due inside the interval (a
    `sleep` in another process, a TCP retransmission, an ARP timeout) runs at
    its deadline after at most 8 quanta, and the clock reaches the end of the
    interval even though the program is still runnable. The host's step
    budget is the number of quanta one interval holds; the call returns
    `.budgetExceeded` while the program runs, which a host should read as
    "more work is ready", not as "time did not pass". See
    [Real-Time Driving](architecture.md#real-time-driving). Under
    `runUntilIdle()` the program still runs to completion at one instant.
  - **Waiting.** `time.Sleep`, `time.After`/`time.Tick`, context timeouts,
    `ReadStdin`, `ReadInput` on standard input, `f.Read`, and network waits park
    the process in the kernel (`ps` shows it sleeping) until logical time
    advances or the descriptor is ready. Nothing fast-forwards the clock, so a
    polling loop costs one wake-up per interval.
  - **Output.** `fmt.Print*`, `fmt.Fprint*`, `f.Write`, and `f.WriteString`
    write to the process's descriptors. When a pipe accepts only part of a
    write, the writing goroutine parks until the reader makes room; writes to
    one descriptor complete in order and are never interleaved or dropped. A
    reader that went away delivers `SIGPIPE`.
  - **Limits.** Strings may reach 16 MiB, slices 4,194,304 elements, and the
    heap 256 MiB. `maximumOutputBytes` does not apply because backpressure
    bounds output. A `[]byte` costs one heap value per byte, so byte-level
    tools should stream through a fixed buffer (`f.Read` into `make([]byte, n)`)
    rather than hold a large file in a slice.
  - A program whose goroutines all wait on each other with no host wait
    outstanding still fails with the deadlock error and status 1.
- `runProgram`, `run`, `go run`, and `go test` complete synchronously inside one
  step: they drive the event loop while goroutines wait (so `time.Sleep`
  advances logical time), keep the output budget and, except for `go run` and
  `go test`, which bound no CPU time as Go's do, the 1,000,000-instruction one,
  send `fmt.Print*` to their output sink, send other descriptors to the
  process when there is one (otherwise to the same sink), and report a wait on
  input the host has not delivered as a deadlock. `startProgram` is the older
  resumable form of that run, which suspends only for `ReadStdin`/`f.Read`.
- A goroutine that parks on the instruction a quantum ends on is recorded as
  parked before the event loop gets its turn, in every run mode.
- Heap statistics are maintained incrementally, and a slice element store or
  in-capacity `append` updates the backing array in place.
- A run that fails while its program left the terminal raw restores cooked
  mode; a program that exits normally keeps the mode it chose, and the shell
  restores cooked mode before its next prompt.
- Exceeding a boundary must return a stable error rather than causing a host trap, infinite recursion, or unbounded allocation.

The executable-image format and ABI have exact versions (format 10, ABI 10). Incompatible, corrupt, or incorrectly targeted images are rejected before launch. Module linking, compound assignment, short-declaration reuse, the `append` spread, variadic functions, and the integer literal forms are compile-time features: they add no opcode and change neither version. Function types, function values, and closures are compile-time features too: a function value is a struct, and what the VM does for one is behind reserved call names. The file, wall-clock, `errors`, formatting, `copy`, `append`-spread, `&T{...}`, new-variable, `$clear`, sized-integer and float (`$num.*`, `$math.*`), full slice (`$slice.full`), network (`$net.*`), sort (`$sort.length`, `$sort.swap`), HTTP and URL (`$http.*`, `$url.*`), locks, conditions, and timers (`$sync.*`, `$time.NewTimer`, `$time.NewTicker`, `$time.AfterFunc`), the environment (`$os.Getenv` and the rest), `$errors.Join`, function-value (`$call`, `$bind`, `$results`, `$nonnil`), and duration (`$time.Duration.<method>`, `$time.Until`, `$time.ParseDuration`) natives are reserved call names, and the dynamic type of an interface value travels in the type name an interface value already had, so they change neither version as well; an image that uses one needs a runtime that provides it. An image built by an earlier compiler keeps running: the type names it boxed call arguments with (`int`, `point`, `*point`) are still understood.

### Names

Two things a name means depend on its scope alone, and both are settled on the syntax tree, a package at a time, before anything is checked. The checker and the compiler then see what they saw before: packages of the run-time library under their own names, and types that belong to a package.

- **Import names.** In a file that says `import f "fmt"`, `f.Println` is rewritten to `fmt.Println` wherever no parameter, variable, or type of an enclosing block is called `f`, and the type `f.Stringer` likewise. The package's own name is then free: the file may have a variable `time` beside `import stdtime "time"`, or import a local package `errors` beside `stderrors "errors"`. Because `time` would now read as the package, every other use of that name in the package is respelled with a middle dot, `time·`, which no source can write; diagnostics print it as the source has it. A local package's name is resolved by the linker, to the same symbol the unnamed import gives. For `import . "fmt"` an exported name that nothing in the file's package or an enclosing block declares is the package's that declares it. Nothing lists what a package of the run-time library declares, so the checker is asked the way a program would ask, as a type, a value, and a call; a name two dot-imported packages declare is `redeclared in this block`, reported when it is used.
- **Alias declarations.** `type Name = T` declares no type, so every use of `Name` is replaced by `T` on the syntax tree, across the whole program, and the declaration is dropped; what is left is checked and compiled as if the program had said `T`. An alias that stands for itself is `invalid recursive type`, and one nothing uses must still name a type.
- **Blank declarations.** Each blank declaration of a package is named `_··N` before linking, so any number coexist; a diagnostic prints `_`. Several package variables of one expression are carried as `$result(index, count, expression)`.
- **Array lengths.** A length that is no literal is kept beside the tree and settled first of the per-package passes, from the constants in scope where it is written.
- **Composite literals.** After aliases are resolved, `GoCompositeLiterals` gives each literal that leaves its type out the type its place says, keeps one reading of each key, folds indexes, counts the elements of `[...]T`, and makes the first operand of `new` and `make` a type. A struct value carries its type name, so it is rewritten under the new name when it passes between a named struct type and the same structure written out.
- **Types declared in functions.** A local type becomes a type of the package under a name of its own, `pair·1`, numbered through the package, and the uses its scope gives it are renamed with it. Two functions that each declare `pair` therefore have two types, an assertion from one to the other fails, and the image names them apart. `%T`, `%v`, and panics print `main.pair` for both, as Go does, and a failed assertion between them ends in Go's `(types from different scopes)`; between types of one name in two packages it ends in `(types from different packages)`. A local type has no methods, as in Go, and costs what a package-level type costs.

### Loop Variables

A VM local is one storage cell, and a declaration that a loop reaches again writes that cell again. That is Go's behavior for every program that takes no pointer to the variable, which is why it costs nothing. Where a pointer can reach a variable that is declared in a loop body or in a `for` or `range` clause, the compiler emits one more instruction, the reserved call `$fresh.<local>`, which unbinds the local from its cell so that the store that follows allocates a new one; pointers to the old cell keep the old variable, which the collector frees when none is left. For the variables of a three-clause `for` the new variable is a copy made before the post statement, as Go specifies.

A pointer can reach a variable when the function takes its address (`&x`, `&x.f`, `&x[i]`), calls a method with a pointer receiver on it, slices it when it is an array, or has a function literal that captures it. The test is by name within one function, so it may renew a variable that did not need it, never the reverse.

### Labels and Type Switches

A label, `break L`, `continue L`, `goto L`, and `fallthrough` are reserved callee names on the syntax tree only (`$label.L`, `$break.L`, `$continue.L`, `$goto.L`, `$fallthrough`). They lower to jumps and add no instruction or native call. A type switch is a `switch` on a guard: a type assertion to the reserved type name `$type`, or `$type.v` when it binds `v`. It lowers to one `typeAssert` with `, ok` for each case type and an `==` with nil for `case nil`. A declaration that a backward `goto` reaches again gets `$fresh` like one in a loop, and a label first stores the constants its block declared before it, for whoever arrives by `goto`. What is wrong with the labels and jumps of a function the parser finds on the tree it made, and the checker reports it among its own errors, in the order of the source.

### Function Values

The VM has no value that is a function, and gained none. A function value is a struct of a type no program can name, `$func`: its first field is the name of a function of the image, and the fields after it are values passed before the arguments when it is called. A call through a value is the reserved call `$call`, with the value as its first operand; `go` and `defer` name `$call` as the function they start, and a nil value panics as a nil pointer does. `fmt` prints a function as an address, as Go does, derived from the name of the function.

- **A function of the program** is the struct with its name and nothing else, and a **method expression** `T.m` is the same with the method's name: a method is a function whose first parameter is its receiver. `(*T).m` for a method declared on `T` is a synthesized function that reads the pointer and calls the method. A method expression of an interface type is the function a method value of the interface calls through; of a library type, the synthesized `$value` function with the receiver as its first parameter.
- **A method value** `c.m` binds the receiver when it is selected: a copy of `c` for a method of `T`, the pointer for one of `*T`. For an interface value the bound value is the interface, and the function is a synthesized one that calls the method by name, so the method that runs is the one of the value the interface held; selecting a method of a nil interface panics there (the reserved call `$nonnil`).
- **A function literal** becomes a function of the image named by where it is written (`$literal.<path>.<offset>`). The checker records the variables of the enclosing functions that the literal uses, those a literal inside it uses among them. The compiled function takes a pointer to each before its own parameters, and begins with the reserved call `$bind.<local>` for each, which makes a local of its frame the very cell the pointer names: inside the literal a captured variable is an ordinary local, and the collector keeps the cell while any function value points to it. A captured variable declared in a loop is renewed each iteration like one whose address is taken, so every literal made in a loop has the variable of its iteration.
- **Named results.** A function that defers returns what its result variables hold after its deferred calls have run, which a deferred literal may have assigned and a recovered panic left as they were. Where a deferred call can reach the results (there are several, or a named one is captured or has its address taken), the function begins with the reserved call `$results.<local>.<local>` and each `return` stores its values in those locals first.

- **`defer` and `go`** of a method of an interface value (`defer resp.Body.Close()`) start it through its method value: the interface and the arguments are read at the statement, and the method is found when the call runs. Of the builtin `close`, they start a synthesized function that closes the channel read at the statement.
- **A function of the run-time library** is the struct with the name of a synthesized function `$native.<package>.$value.<pkg>.<Name>`, whose body is the call lowered as a call the program wrote; a method value of a library type binds the receiver (the handle, for `sync.Mutex` and the like) as the first field.

`f(g())` adds no instruction. The checker and the compiler check or make the inner call once and go on with a call whose arguments are names for its results (`$forwarded.<n>`, `$pinned.<register>`), so each callee takes them as written arguments. The calls the callee is made of run first, then `g`, then the callee reads its variable or receiver.

A literal's body is lowered after the function it is written in, not inside it, and each kind of statement and expression is checked and lowered by a function of its own, so statements and literals nested deeply cost little stack, also in an unoptimized build, where one function for all kinds made each level cost the frame of the largest.

### Embedding

An embedded field is an ordinary field named by its type. For each promoted method of a declared struct type the compiler declares a method `Outer.m` (with the receiver `*Outer` when Go has it in the pointer's method set alone) that selects the field and calls its method; interface dispatch, `fmt`, and `errors` find it by the dynamic type's name. A promoted field, and a promoted method called or selected directly, is compiled as the explicit selection (`d.base.id`) and costs nothing more. An embedded interface is replaced by its methods before checking. A struct type with an embedded field or a tag has `E` and `G<n>:<tag>` in its descriptor, which needs a runtime that reads them.

### Library Functions in Go

A native cannot call the program, so the library functions that take a callback are Go text held by the compiler (`SourceLibraryText.swift`) and linked by `GoSourceLibrary` before checking, like a package of the module: `sort.Slice` is the program symbol `sort.Slice`, types included, and only the declarations a program reaches are linked, so a program that names none compiles to the image it had. A package may be native in part (`sort.Ints`, `sync.Mutex`). `net`, `net/http`, `net/url`, and the members of `io` and `strings` that are written in Go (`io.ReadAll`, `io.Copy`, `strings.NewReader`) come the same way, as do package-level variables with their initializers (`http.DefaultServeMux`, the `Err` values): each package with something linked is a unit after the program's that initializes before it, a package after those it names. The text is the Go files of `Sources/SwiftixGoLibrary`, generated into `SourceLibraryText.swift` by `Scripts/generate-go-library.py`, and a test fails when that file is stale; `native.name(...)` in the text is the one way to call a native (`$sort.*`, `$net.*`, `$http.*`, `$url.*`); the guide to adding a package is at the top of `SourceLibrary.swift`. `fmt.Fprintf(w, ...)` with `w` no file compiles as `w.Write([]byte(fmt.Sprintf(...)))`. In the text, `native.name(...)` is the reserved call `$name` of the package; `$sort.length` and `$sort.swap` serve a slice held in an `any`.

### `net/http`

The server and the client are Go: the accept loop, the request parser, `ServeMux` with Go 1.22's method, host, and wildcard patterns, the response writer, and the client run as code of the program on `net.Listen`, `Accept`, `Read`, and `Write`, and `r.RemoteAddr` is the connection's `RemoteAddr().String()`. Each connection is served in a goroutine of its own, a handler is any function value, a panic in one ends its request alone, and what the server sends is what Go's sends byte for byte apart from `Date`: the status line, `Content-Length` or chunks at Go's 2048-byte boundary, the sniffed `Content-Type`, HEAD, 204, `Connection: close`, pipelining, and the 400, 404, 405, and 505 answers. `http.Handler`, `http.HandlerFunc`, `http.Handle`, `http.NewServeMux`, `http.Server{Addr:, Handler:}` with `ReadTimeout`, `ReadHeaderTimeout`, `WriteTimeout`, `IdleTimeout`, `ConnState`, `Shutdown`, `Close`, and `RegisterOnShutdown`, `http.TimeoutHandler`, `http.StripPrefix`, `http.Error`, `http.NotFound`, `http.Redirect`, and middleware of the shape `func(http.Handler) http.Handler` compose as in Go, and a struct that embeds `http.ResponseWriter` is one. The client has `Get`, `Head`, `Post`, `PostForm`, `NewRequest`, `NewRequestWithContext`, and `Client.Do` with redirects and `Client.Timeout`. `r.Context()` is cancelled when the handler returns or the client goes away. Closing a listener or a connection wakes a goroutine blocked in `Accept` or `Read` with `use of closed network connection`. Images that hold the instructions of the earlier stub (`httpHandleFunc`, `httpListenAndServe`, `httpGet`) still run; new code does not emit them. `swiftix-go run` gives the program a loopback interface, so a program can reach a server it started.

### `encoding/json`

The API and the error types are Go text of the library; the walk over a value is native. It reads the descriptor an interface value carries (the fields, their tags, embedding, and the underlying type of every named type the value reaches), so `json.Marshal(v)` costs the program one call. Where Go calls a method of the program (`MarshalJSON`, `MarshalText`, `UnmarshalJSON`, `UnmarshalText`, `IsZero`), the walk stops under a handle, the library's text calls the method, and the walk resumes; what a stopped walk holds is a root of the collector. Work is kept on an explicit stack, so the depth of a value costs no thread stack; Go's limits apply: a decode deeper than 10,000 fails with `exceeded max depth`, and an encode reports a cycle after 1,000 levels of pointers. A program that does not import the packages links none of them.

### Interface Values

A value converted to an interface is boxed with a descriptor of its static type: the type itself and the underlying type of every named type it reaches. Only an `int`, a `string`, and a `bool` travel bare, because the value shows the type. The descriptor is what `fmt` formats by, what `==` and a type assertion compare, and where a method call through the interface finds the method.

- **Assertions to a concrete type** compare type identity, so a `byte` is not an `int`, a named type is not its underlying type, and `[]byte`, `map[string]int`, and struct types assert as themselves.
- **Assertions to an interface type** succeed for the types that implement it. The compiler, which sees every package of the program, lists them from exact method signatures (name, parameter types, result types, and whether the receiver is a pointer), and the VM looks the dynamic type up in that list. A failed assertion without `, ok` panics with Go's message: `interface conversion: main.file is not main.sizer: missing method size`.
- **Method calls** through an interface dispatch on the dynamic type, dereference a pointer for a value receiver, take several results (`value, ok := store.Get(key)`), and pack a variadic parameter.
- **Floats.** `GoValue` has no float: a `float64` or a `float32` is its IEEE 754 bit pattern in an integer, every operation on it is chosen by the checker and lowered to a reserved call (`$num.fadd` and the rest), and it is boxed with its descriptor, so `fmt` and assertions see a float.
- **Sized integers.** A value of a sized integer type is boxed with its descriptor, like a `byte`, so `%T`, `%v` of an unsigned 64-bit value, `==`, and assertions see the type.
- **Locks.** A `sync.Mutex` and a `sync.WaitGroup` are VM handles. Each value that holds one gets a handle of its own when the VM makes or copies it (`make`, `append`, `copy`, `clear`) and when the program copies it (the reserved call `$sync.copy`, emitted only for types that hold one), so a lock behaves as a value, as in Go. Unlocking an unlocked mutex is a fatal error.
- **Handles.** `*os.File` is a value of the interfaces its methods satisfy (`io.Reader`, `io.Writer`, `io.Closer`, a program's own), with `nil` for a zero value. `net` is Go text: `net.Conn`, `net.Listener`, `net.Addr`, and `net.Error` are its interfaces, and a `*net.TCPConn` or `*net.TCPListener` holds a descriptor and calls seven natives (`$net.listen`, `$net.accept`, `$net.dial`, `$net.read`, `$net.write`, `$net.close`, and `$net.deadline`) that return codes the text turns into Go's errors; the VM keeps the deadlines and the bytes received. The handles and instructions of the native connections stay for images built before and are no longer emitted. `context` is Go text: `WithCancel`, `WithTimeout`, `WithDeadline`, `WithValue`, `Done`, `Err`, `Value`, `Deadline`, `Cause`, `AfterFunc`, and `context.Context` an interface a program implements. The native context instructions stay for images built before and are no longer emitted.
- **Library types.** A defined type of the library (`time.Duration`) is boxed as a defined type of the program is, with what it is defined as. Its methods are functions the VM provides under the names a program's methods have (`time.Duration.String`), each one native call and no part of an image. The VM matches a library type against an interface by method name and count, and the compiler writes a `!time.Duration` line into the assertion target where the types differ.
- **Native calls into guest code.** `fmt` and `errors` run a program's `Error`, `String`, `Unwrap`, and `Is` methods. A native cannot run guest code, so the instruction that needs a method calls it like any function and then executes again with the result; a native that needs several methods repeats this once per method. A formatting call therefore costs one VM instruction plus the instructions of the methods it runs.

### Panics

A run-time error of the program does not end it at once. The instruction that meets the error raises a panic in the function that was executing, that function's deferred calls run, and so do its callers' while the panic travels up the goroutine's stack. A deferred function that calls `recover` stops it, and the function that panicked returns the zero values of its results (or what its named results hold).

| Error | `recover()` prints | `%T` |
| --- | --- | --- |
| `p.field`, `*p`, or a method call with a nil `p` or a nil interface | `runtime error: invalid memory address or nil pointer dereference` | `runtime.errorString` |
| `x[i]` out of range | `runtime error: index out of range [5] with length 3`, or `[-1]` for a negative index | `runtime.boundsError` |
| `x[a:b]` out of range | `runtime error: slice bounds out of range [:5] with capacity 3` (`with length` for a string or an array), `[2:1]`, `[-1:]` | `runtime.boundsError` |
| `a / b`, `a % b` with `b == 0` | `runtime error: integer divide by zero` | `runtime.errorString` |
| `1 << n` with `n < 0`; `make([]T, n)` with `n < 0` | `runtime error: negative shift amount`; `runtime error: makeslice: len out of range` | `runtime.errorString` |
| An assignment to an entry of a nil map; a send on or a second `close` of a closed channel; `close` of a nil channel | `assignment to entry in nil map`, `send on closed channel`, `close of closed channel`, `close of nil channel` | `runtime.plainError` |
| `v.(T)` without `, ok` when `v` is not a `T` | `interface conversion: interface {} is string, not int` | `*runtime.TypeAssertionError` |

- The recovered value is a `runtime.Error`: `err, ok := r.(error)` and `r.(runtime.Error)` succeed and `err.Error()` is the text above. Two such values are equal when they say the same, as Go's are; no heap cell is allocated to report one.
- A panic nothing recovers ends the run with `GoRuntimeError.panicError(message)`, printed as `panic: <message>`, after every deferred call of the goroutine has run. A file-backed program exits with status 2, as a Go program does.
- After the first line comes the goroutine's trace as Go prints it: `goroutine 1 [running]:`, then for each frame its function (`main.f(...)`) and, on the next line after a tab, its file, line, and offset (`/path/main.go:13 +0x16`). The VM prints it when `GoVirtualMachine.tracesPanics` is set, which is off by default and which the `go` tool, the host tool, and the executable loader set; the lines come from a `.lines` file the build cache keeps beside an image. See Known Gaps for what differs.
- The message of a value the program panicked with is Go's: an `int`, a `string`, or a `bool` as it is; one of a named type with the type around it (`main.code(4)`, `main.name("x")`); an error by its `Error` method and a value with a `String` method by that, which run as the goroutine's last frame; and anything else by its type and where it lies (`(main.failure) 0xc000012000`, `([]int) 0xc000013000`).
- A panic that begins while another is not over is reported after it, as Go reports them: a deferred call that panics while its function is panicking prints `panic: first` and, on the next line after a tab, `panic: second`; one that recovers and panics anew marks the first `[recovered]`. A recovered panic is over when the call that recovered it returns. Each frame keeps the panics that came before the one it is ending with, so nothing is kept for a program that does not panic twice.
- The argument of `panic` is converted to `interface{}` like any other, so `recover` returns it with its type: `%T` of a recovered `code(4)` is `main.code`.
- A goroutine recovers only its own panics; an unrecovered panic in any goroutine ends the program.
- `fmt` recovers a panic of an `Error` or `String` method it calls and prints `%!v(PANIC=String method: runtime error: ...)`.
- A fault of the machine itself is not a panic and cannot be recovered: a malformed image, a dangling heap cell, an exceeded resource limit, or a deadlock ends the run with its own `GoRuntimeError`.

### Formatting

`fmt.Print`, `Println`, `Printf`, `Fprint`, `Fprintln`, `Fprintf`, `Sprint`, `Sprintln`, `Sprintf`, and `Errorf` follow Go's `fmt`. The programs in `GoConformanceTests` were run through Go 1.24.5 and Swiftix Go must print the same bytes (addresses aside, which differ between two runs of Go as well); `GoFormatVerbTests` pins further cases that were checked the same way.

| Part | Supported |
| --- | --- |
| Verbs | `%v` `%+v` `%#v` `%T` `%p` `%d` `%b` `%o` `%O` `%x` `%X` `%c` `%q` `%U` `%s` `%t` `%%`, and `%w` in `fmt.Errorf` |
| Flags | `-`, `+`, `#`, space, and `0` |
| Width, precision | Decimal or `*` from an operand, capped at 1,000,000 as in Go; width counts code points |
| Argument indexes | `%[2]d`, `%[1]*d`, `%[3]*.[2]*[1]d`, with Go's `%!d(BADINDEX)` |
| Operands | Every type of the dialect, formatted by its static type: a `byte` is a `uint8`, a nil slice is `[]` and a nil map `map[]`, a map prints sorted by key, a pointer to a struct, slice, array, or map prints `&{...}` as an operand and its address inside another value, `[]byte` is text for `%s`, `%x`, and `%q` |
| Methods | A `Format` method (`fmt.Formatter`) prints its value under every verb but `%T` and `%p`, with a `fmt.State` that is a `*fmt.pp`, and a `GoString` method under `%#v`, before `Error` and `String`. `Error()` and then `String()` under `%v`, `%s`, `%q`, `%x`, and `%X`, for an operand and for any value inside it that is not behind an unexported field. A method is called on a nil pointer too; one that panics prints `%!v(PANIC=String method: ...)`, or `<nil>` when its receiver is a nil pointer |
| Results | `Sprint` and `Print` put a space between operands when neither is a string; the output functions return the byte count and the error of the write, if any |
| Mistakes | Go's markers: `%!d(string=hi)`, `%!d(MISSING)`, `%!(EXTRA int=1)`, `%!(NOVERB)`, `%!(BADWIDTH)`, `%!(BADPREC)`, `%!d(BADINDEX)` |

What differs from Go:

- The error of a failed `*os.File` method has no concrete type of its own (see Known Gaps): `%T` prints `*errors.errorString`, and `%+v`, `%#v`, and `%d` print that shape.
- A `time.Time` prints by its `String`, by `GoString` under `%#v`, and as Go's raw `{wall ext loc}` struct behind an unexported field. A `time.Duration` prints by its `String`, computed natively without a method frame.
- A pointer prints an address of the VM's heap (`0xc000012000`), which identifies the value but is not a machine address.
- A type of the program's root package is named `main.T`; this is wrong only under `go test` of a package that is not `main`.

A result is bounded by the string limit, and printed text by the run's output budget.

### Files

A `*os.File` the program opens is a handle, not a descriptor number, and a handle is never reused. A file used after `Close` therefore fails with `file already closed` even when a later `os.Open` was given the same descriptor, and it never reaches the other file.

- `os.OpenFile(name, flag, perm)` accepts the flags listed above with Go's Linux values; any other bit is `invalid argument`. A new file gets `perm` under the process umask, and a missing parent directory is an error rather than being created.
- `f.ReadAt` and `f.WriteAt` use the kernel's `pread`/`pwrite`: they leave the file offset alone, `ReadAt` returns `io.EOF` with a short count at the end of the file, a write past the end leaves a zero-filled gap, and `WriteAt` on a file opened with `O_APPEND` is refused as in Go. `ReadAt` fills its slice in one accounting pass, which is what a page-sized read needs.
- `f.Sync` succeeds for any open file: a VFS write is complete when it returns. The VFS itself is in memory; durability across a restart belongs to the host's snapshot of it.
- `os.Rename` keeps the node, so a file that is open across the rename keeps writing to it; this is the write-temporary-then-rename pattern. `os.Remove` removes a file or an empty directory.
- Files still open when a synchronous run (`go run`, `go test`, `runProgram`) ends are closed, in the order they were opened. A file-backed process leaves that to its exit.
- A run without a process has no file system: every call returns an error ending in `no file system`.

### Wall-Clock Time

A `time.Time` is an instant on the hosting kernel's wall clock, which is the Unix epoch at logical time zero unless the host anchored it with `Kernel.setWallClock`. It follows logical time, so it advances only as the host advances the event loop, and a run without a process counts from zero. `time.After` and `time.Tick` deliver the same instants. There is no monotonic reading: an interval measured across a host re-anchoring of the clock includes the jump.

A time in the local location is held as the integer of its nanoseconds since the epoch, except that 0 is Go's zero time, January 1 of year 1. The epoch itself, a time in another location, and one outside the range of that integer are an array of seconds, nanoseconds, and location. That is why an image built when a time was only its nanoseconds keeps running.

## Distribution and Host Tools

The sibling `coreutils` repository builds official base commands from Go source into a native `.pkg`, compiling each command as a module build that imports a shared local package; `SwiftixDistribution` verifies and installs that package into the rootfs. Running those commands requires only `SwiftixGoRuntime`; distribution content does not enter the core target.

macOS and Linux provide:

```text
swiftix-go build -o hello .
swiftix-go run . arg
swiftix-go test ./...
swiftix-go exec --root . hello -- arg
```

The host adapter copies an explicit workspace into guest `/workspace`, rejects symlinks, and limits file count, individual file size, and total bytes. Guest writes do not modify the host directory. The executable ships under the shared `swiftix-toolchain` version.

See the [product roadmap](roadmap.md) for shared versioning, signing, notarization, and release gates. Every newly supported semantic requires positive, error, and resource-boundary coverage; unsupported behavior must retain stable diagnostics.
